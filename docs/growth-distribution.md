## LinkedIn launch draft

Our own website audit found a basic problem: a template page described downloads it did not provide.

That is the kind of issue a long checklist can miss if nobody follows the actual visitor journey.

We have documented the finding and the correction in an AuditWeb self-audit. We have also created a reusable toolkit with a client questionnaire, report template, prioritisation worksheet and implementation tracker.

The templates are editable Markdown files. There is a printable 50-check PDF too. No email required.

Use them to connect each finding to evidence, an owner and a verification step:

## Short demonstration script

1. Show the free HTML checker and state its scope: pasted HTML only, no live crawl.
2. Load the example and point out the noindex directive and missing alt attribute.
3. Run the check. Read the two findings and explain that noindex may be intentional.
4. Remove the noindex directive and rerun. Show that the observation changes.
5. Download the report and show how a finding becomes an assigned task in the toolkit.

Suggested title: Check page HTML for canonical and noindex issues - a practical example.

## Weekly operating cadence

- One useful demonstration or finding per week from actual work.
- One contextual reference to the toolkit where an existing guide genuinely needs a handoff document.
- Review the named GSC page cohort weekly. Preserve query/country/device context.
- Review `resource_download`, `html_check_complete` and `audit_service_click` events for consented visitors.
- Confirm enquiries in the receiving system separately. These events are interest signals, not verified leads or revenue.
- Record publish dates and channels. Compare complete 28-day windows before drawing conclusions from small counts.

Do not send pasted HTML, submitted URLs, names or emails to analytics. The event implementation sends only fixed event names and owned download paths.
