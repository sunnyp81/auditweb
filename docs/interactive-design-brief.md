# AuditWeb category and interactive evidence brief

Date: 6 September 2026. Audience: site owners choosing their first audit tool and SEO practitioners assembling an audit workflow. Visitors need a suitable tool, its limits and a useful guide before they need a long buying article. Primary category action: inspect a shortlist and follow a relevant tool guide. Homepage action remains professional audit scope, supported by a hands-on view of our own recorded evidence.

Current rendered findings: the tools page uses Article layout with a sidebar and a long contents-first introduction. At 390px its height is 17,361px and child guides start at 13,445px. The homepage has no main-content buttons; its real evidence sheet is passive. Unsupported claims about testing hundreds of sites and stale prices undermine the category's credibility.

Preserve Astro, static crawlable HTML, established navy/cyan, Inter for readable UI continuity, existing child URLs, header, footer and working checker. No new package or external runtime. Subject anchors: audit inspection records, response status transitions, evidence/limitation columns. Use cool-white inspection surfaces within the navy shell, clear rows grouped by audit task, and state changes that explain findings. No invented scores or live scanning animation.

Hierarchy: category name and purpose → task selection → tool entries with scope and limitation → shortlist comparison → specialist guides → selection method. Mobile: labelled native controls, vertically readable tool records, no sticky overlay, explicit table scrolling. Full directory and guides remain available without JavaScript. Owned checker is a separate disclosed route. Each vendor entry carries its own source-check date; plan terms are confirmed at the vendor.

Competitive research: Screaming Frog exposes dense capability lists; Ahrefs emphasises product screenshots and health scores; Sitebulb emphasises crawl visualisation and prioritised hints. AuditWeb should instead make tool boundaries comparable and connect choices to the underlying audit task. Publisher sources were opened on 6 September 2026; these are documentation-based descriptions, not comparative lab tests.

Opus was asked for a read-only design critique after our rendered audit, using desktop/mobile screenshots and existing source. Its recommendations and actual model identity will be recorded with validation. Final choice must preserve accessibility, truthful evidence and source-backed content.

Release gates: two desktop/mobile rendered critique passes, interaction and no-JavaScript tests, accessibility at 1440/390/320px, keyboard and reduced-motion checks, production build, rendered HTML validator, internal links/schema, secret/dependency scans, deployed commit and live browser verification. Semantic article rules that suppress discovery links are inapplicable to the user's explicit category-page requirement.
